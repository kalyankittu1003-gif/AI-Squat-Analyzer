# AI Squat Analysis Application

This application analyzes side-view videos of barbell back squats using MediaPipe for pose tracking and Gemini 1.5 Pro for expert assessment based on standard powerlifting rules.

## Architecture and Model Choices
- **Frontend**: Streamlit. Selected for its rapid prototyping capabilities for UI and video playback, suitable for a 4-6 hour time box.
- **Computer Vision**: OpenCV and Google MediaPipe Pose. MediaPipe provides reliable, cross-platform body pose landmarks which are robust even in gym environments.
- **AI Agent (LLM)**: Google Gemini 1.5 Pro (via `google-generativeai` SDK). Used for reasoning over the structured output generated by MediaPipe against the provided skill document. 
- **Skill Extraction**: The reference PDF was extracted into a markdown format (`squat_skill.md`), structuring the 8 main criteria, identifying what is and isn't side-view assessable.

## Setup Instructions

1. **Prerequisites**: Python 3.9+
2. **Environment Variable**: You must provide a Gemini API key. Create a `.env` file in the `squat_analyzer` directory:
   ```
   GEMINI_API_KEY="your_api_key_here"
   ```
3. **Install Dependencies**:
   ```bash
   python -m venv .venv
   # Windows:
   .\.venv\Scripts\activate
   # Mac/Linux:
   source .venv/bin/activate
   
   pip install -r requirements.txt
   ```
   *(Note: FFmpeg is recommended on your system PATH for converting output videos to web-compatible MP4, but OpenCV's default writer is also used as a fallback.)*

4. **Run the Application**:
   ```bash
   streamlit run app.py
   ```

## Trade-offs and Limitations
- **Barbell Tracking**: Directly detecting a barbell requires a custom object detection model (e.g., YOLO) which adds significant complexity and latency. Given the time constraints, the shoulder landmark is used as a reliable proxy for the low-bar position, which tracks the barbell path accurately enough for assessment.
- **Occlusion**: 2D pose estimation from a single view can struggle with occlusion (e.g., plates blocking the hips/knees). MediaPipe handles basic occlusion well, but results might degrade if the plates completely hide the joints.
- **Gaze Direction**: Estimated using the ear and nose landmarks. A more complex head-pose estimation model could provide higher accuracy.
- **Latency**: Processing the video frame-by-frame with MediaPipe takes a few seconds, but is generally fast enough for a consumer prototype.

## Build Notes
- Time spent: ~3 hours.
- Cost: Gemini API cost is negligible per video due to the low token count of the structured JSON data compared to sending the raw video directly to the model.

## Known Issues
- Very short or partial movements might not be detected as reps if the hip vertical displacement does not exceed the heuristic threshold.
- The default video codec written by OpenCV (`mp4v`) sometimes does not play natively in all browsers within Streamlit. FFmpeg is used to transcode to `libx264` if available on the host system.
